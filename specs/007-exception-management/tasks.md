2. **Re-read before each task**: the section the task references:
   - research.md (R#);

   - plan.md "Key Design Notes" (KDN #).

   **Do not invent alternatives.** The strings and values in contracts/api.md § Text templates and § Acceptance fixtures are exact. Assert them literally.
3. **Forbidden**:
   - new dependencies;
   - `any`, `TODO`s, and non-null `!` (use `.at()` with a check and throw an invariant `Error`);

   - inline permission checks in services (always call `rules/policy.ts`, KDN 5);
   - edit or delete endpoints for comments, evidence, snapshots, exceptions, or a delete endpoint for teams;
   - email, websockets, workflows, automation or risk features.
4. **No changes to earlier features' behavior**:
   - do not change any 003, 005 or 006 response shape, rule, text or seed row (§39, §40);
   - every existing test must pass **unchanged**, except the additions named in a task.
5. **Checkpoints**: after each **phase**, run its **Checkpoint**. Fix every failure, tick the boxes, and commit with Conventional Commits (`feat(exceptions): …`, `feat(notifications): …`, `feat(teams): …`, `feat(shared): …`, `test(exceptions): …`, `feat(web): …`), one commit per task or small group of tasks.

7. **Shared builds**: rebuild shared after every change to `packages/shared`: `pnpm --filter @opsgraph/shared build`.
8. **Mutating service methods** (KDN 2): `now = new Date()` is read **once**, first, and passed everywhere. Then one `$transaction` holding the conditional update (or inserts), the audit row and the notifications. Analyses (005/006) run **before** the transaction, never inside it (KDN 3).
9. **Web** (KDN 9): parse every response with its shared schema through `apiFetch`; show only the actions in `permissions`; send `expectedVersion` from the loaded detail; every section and tab handles its own loading and error state; badges are text plus colour. Read `apps/web/src/lib/api-client.ts` and `apps/web/src/lib/format.ts` before the first web task and reuse their helpers.

**Decisions fixed by this task list** (they close small gaps in the design documents; do not revisit them):
- D1. The new user reference schema is named `ActorRefDtoSchema` (type `ActorRefDto`), never `UserRefDtoSchema`, because 005 already exports that name (contracts/api.md § Shared building blocks).
- D2. `Errors.invalidState(message: string)` takes a ready message. The message builders live in `rules/transitions.ts` (T010). Closed-state refusal (FR-014) uses `` `${ACTION} is not allowed while the exception is CLOSED. Reopen it first.` `` with ACTION one of `EDIT`, `ASSIGN`, `ESCALATE`, `REFRESH_ANALYSIS`, `ADD_EVIDENCE`, `DETACH_EVIDENCE`, `LINK_ENTITY`, `UNLINK_ENTITY`.
- D3. A mutation that needs an unresolved exception, on a RESOLVED or VERIFIED one, gives `` `${ACTION} is not allowed while the exception is ${STATUS}. It must be unresolved.` `` (409 `INVALID_STATE`). This covers `ESCALATE`, `REFRESH_ANALYSIS` and `EDIT_SLA_DUE`.
- D4. `PATCH` with `slaDueAt` must be after the exception's `createdAt`, else 400 on `slaDueAt` with `SLA due time must be after the creation time`. This keeps `slaAtRiskAt <= slaDueAt` and `windowMs >= 1`. `slaAtRiskAt()` still clamps the window at 0 as a safety net.
- D5. Permission refusals write `auth.forbidden` with `metadata: { method, path, role, exceptionId, action }`. Team routes are guarded by `@Roles('ADMIN')`, so their refusal rows keep `RolesGuard`'s existing metadata `{ method, path, role }` (the guard is not changed).
- D6. `POST /exceptions` does not apply the assignment policy to `owner` (spec FR-016: "Create: every signed-in user"). Only the owner's validity (ACTIVE user, existing team) is checked.
- D7. At creation, a `relatedEntityIds` entry equal to the chosen root-cause entity is dropped (the ROOT_CAUSE link covers it). An entry equal to the subject, or repeated, is 400 `relatedEntityIds.<i>` `Entity is already linked`.
- D8. The Entity 360 Exceptions section (T035) cannot show the entity's link role (the list DTO has no role). It shows `Subject` when `exception.subject.id` equals the entity id and `Linked` otherwise.
- D9. `ExceptionsService.create` takes a third argument `opts?: { rootCauseEvaluatedAt?: string; createdFrom?: 'SEED' }` for the seed only. The HTTP schema never accepts `SEED`.
