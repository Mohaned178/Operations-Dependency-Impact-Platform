- D3. `Errors.versionConflict(currentVersion, subject)`: 008 already added the optional `subject` parameter (`'exception' | 'investigation'`). This feature widens the union with `'risk configuration' | 'SLA term'` (plan and contracts call the parameter `noun`; keep the name `subject`). Default and 007/008 calls are unchanged (T009).
- D4. The risk's latest assessment is found through `risks.latest_assessment_seq` (data-model §1a). Research R12's `latestAssessmentId` does not exist.
- D5. `evaluateEntity(input, rule, asOf, ctx)` takes `ctx: { configVersion: number; graphVersion: string | null; termsDigest: string | null }` for the payload fields. The engine returns `RESULT`, `BELOW_THRESHOLD` or `NOT_APPLICABLE` (data-model §4b); the **API** maps `RESULT` to `RISK` and adds `DISABLED` for a disabled rule (contracts `RiskPreviewResponse`). Fixed `NOT_APPLICABLE` reasons (`gateReason` in `candidates.ts`): `Rule applies to <comma list of types> only`; `<STATE> is a terminal state`; `<name> is not impaired` (gate OWN_IMPAIRED); `Neither <name> nor a direct dependent is impaired` (supplier gate); `Nothing depends on <name>` (gate HAS_DIRECT_DEPENDENT); `No running SLA commitment` (gate RUNNING_CLOCK).
- D6. Evaluation numbers and risk numbers are **never** asserted as absolute values (`resetDb` does not restart sequences, KDN 8). A test that needs "evaluation #N" reads N from an earlier response (the message of K9 step 4 uses the number returned by step 3). The only absolute-number test is the fresh-database sequence check of T010, which asserts `>= 10001`.
- D7. A manual evaluation without `asOf` uses `max(now, latest completed asOf)`, like scheduled ones (research R10); spec FR-018's "start time" is the same value except when the latest completed `asOf` lies in the future.
- D8. Scheduler constants are exported from `risk-scheduler.ts`: `DATA_CHANGE_DEBOUNCE_MS = 5_000`, `BUSY_RETRY_MS = 15_000`. The constructor takes optional overrides for unit tests (fake timers). The one e2e with the scheduler enabled waits for the real debounce by polling for up to 30 s. `RISK_EVALUATION_INTERVAL_MS` keeps its minimum of 60,000 and the e2e does not depend on it.
- D9. `RiskModule` imports `PrismaModule`, `AuditModule`, `GraphModule`, `TracingModule`, `ExceptionsModule`, `UsersModule` (research R1). The system actor is 007's existing exported constant (find it with `grep -rn "system: true" apps/api/src/exceptions/`); never redefine it.
- D10. `bigint` values (`graphVersion`, assessment `seq`) are serialized as **decimal strings** in every DTO and payload.
- D11. Clock keys: `term:<termId>:<orderId>` and `record:<slaEntityId>` (contracts § SlaClockDto). A clock's `attachment.origin` is `SOURCE` when any GOVERNS assertion between the pair is SOURCE, else `MANUAL` before `INFERRED` (research R2). `source SLA_RECORD` clocks have `attachment: null` and count as SOURCE for confidence.
- D12. `GraphRepository.reachBatch` returns **terminal** entities as rows too (they are not expanded). Consumers drop terminal entities from every count and list. The 10,000-entity cap per start and the `lowerBound` flag are applied by `RiskInputsReader`, not by the repository (research R5).
- D13. New pure files not listed in plan.md, fixed here: `apps/api/src/risk/engine/types.ts` (engine input types), `apps/api/src/risk/engine/test-inputs.ts` (spec-only builders), `apps/api/src/risk/sla/build-clocks.ts` (pure clock builder, T024), `apps/api/src/risk/evaluation/evaluation-claim.service.ts` (the lock, T030).
- D14. The lock is the `risk_evaluations` row itself: status RUNNING plus the partial unique index `risk_evaluations_one_running` (data-model §1b). No advisory locks, no extra table (research R10).
- D15. `RiskInputsReader` has two public methods: `findCandidates(config, terms, asOf, entityId?)` and `buildInputs(candidates, asOf, config, terms)`. The runner calls them for all entities, the preview for one entity. Both go through the same code, so a preview equals an evaluation (FR-022).
