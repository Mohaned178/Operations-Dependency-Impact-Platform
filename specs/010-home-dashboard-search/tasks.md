**Decisions fixed by this task list** (they close gaps and inconsistencies in the design documents; do not revisit them):
- D1. **Snapshot-based drill targets always carry `snapshotId`.** Contracts route 2 and 3 default to the latest completed snapshot, but Home selects the latest completed snapshot with `as_of ≤ evaluatedAt` (R13). So every `AT_RISK_ORDERS` and `BLOCKERS` drill `query` built by `drill.ts` contains `snapshotId` of the snapshot Home used. Shapes: category figure `{ snapshotId, category, currency }`; currency total `{ snapshotId, currency }`; value unknown `{ snapshotId, valueUnknown: 'true' }`; blockers count `{ snapshotId }`; a blocker's orders `{ snapshotId, rootCauseEntityId }`.
- D2. **Drill kind → endpoint → total extraction** (the contracts say only "total = value"; this is the exact rule, used by `drill.ts` and by T038):

  | `kind` | Endpoint | Total taken from |
  |---|---|---|
  | `EXCEPTIONS` | `/api/exceptions` | `total` |
  | `INVESTIGATIONS` | `/api/investigations` | `total` |
  | `RISKS` | `/api/risks` | `total` |
  | `SLA_CLOCKS` | `/api/sla-clocks` | `total` |
  | `AT_RISK_ORDERS` | `/api/overview/at-risk-orders` | `summary.orderCount` (money: `summary.sums`) |
  | `BLOCKERS` | `/api/overview/blockers` | `total` |
  | `FREQUENT_ROOT_CAUSES` | `/api/overview/frequent-root-causes` | `items.length` (the route has no `total`) |
  | `ENTITY_FINDER` | `/api/entity-finder` | not used by any Home figure; only saved filters and the Entities page use it |

  If 007, 008 or 009's list response has no `total` field, stop (rule 7).
- D3. **`StoredCriteriaSchema` and `EntityFinderCriteriaSchema` live in `search.ts`** (data-model §2c lists them under both `search.ts` and `saved-filters.ts`; `saved-filters.ts` must import from `search.ts`, never the other way, to avoid a circular import). `search.ts` imports `SnapshotRefSchema` from `overview.ts`; `overview.ts` imports neither `search.ts` nor `saved-filters.ts`.
- D4. **The `csv` helper** is 007's (or the `csvEnumArray` that 009 moved to `common.ts`). Find it with `grep -rn "csv" packages/shared/src/common.ts packages/shared/src/exceptions.ts`. Import it; never redefine it.
- D5. **Search trigram threshold**: Postgres cannot bind a parameter in `SET LOCAL`. Inside one interactive `prisma.$transaction(async (tx) => …)` per group, run `` tx.$queryRaw`select set_config('pg_trgm.similarity_threshold', ${String(SEARCH_LIMITS.similarityThreshold)}, true)` `` first (identical to `SET LOCAL`, parameterizable), then every query of that group on `tx`. The three groups run in parallel in three transactions.
- D6. **Search order**: entities `tier, display_name COLLATE "C", id`; exceptions and investigations `tier, title COLLATE "C", number`. Spec FR-029's "then identifier" is implemented as the entity id (uuid text) for entities, because an entity can have several identifiers.
- D7. **Evaluation, snapshot and risk numbers are never asserted as absolute values** (`resetDb` does not restart sequences, KDN 8). A test that needs "snapshot #N" reads N from an earlier response. The only exception is a fresh-database check, which this feature does not need.
- D8. **`SnapshotRunner` options**: its constructor takes optional `{ maxAnalyzedOrders, analysisConcurrency }` (defaults `OVERVIEW_LIMITS.maxAnalyzedOrders` and `env.OVERVIEW_ANALYSIS_CONCURRENCY`) so tests can set the cap to 3. `SnapshotTrigger` exports `SNAPSHOT_BUSY_RETRY_MS = 15_000` and takes an optional override in its constructor (fake timers). The single e2e with automatic snapshots enabled polls for up to 30 s.
- D9. **Section failure text**: `reason` is `<Section label> is unavailable: <message>`, where `<message>` is the message of an `AppError`, or `an internal error occurred` for any other error (the error itself is logged with the correlation id). Section labels: `Exceptions`, `Risks`, `SLA`, `Revenue at risk`, `Unresolved blockers`, `Frequent root causes`, `Data freshness`, `Assigned to me`.
- D10. **Assigned counts are never added**: `exceptionsMine` and `exceptionsMyTeams` are each their own 007 view total. The list `assigned.exceptions` is mine first, then my teams, de-duplicated by id, at most 5.
- D11. **Stale sources of revenue at risk**: the distinct `state_source_system` of snapshot rows whose reasons include `IMPAIRED`, intersected with the systems that are `STALE` at Home's `evaluatedAt`, sorted with `compareCodeUnits`.
- D12. **Finder category criterion** uses the latest completed snapshot regardless of `evaluatedAt` (R8); `meta.snapshot` states which one. This differs from Home (R13) on purpose; do not "fix" it.
- D13. **New pure files not listed in plan.md**: `apps/api/src/search/rules/tiers.ts` (TypeScript oracle of the SQL tiers, T013), `apps/api/src/search/rules/matches.ts` (matches builder, T013), `apps/api/src/overview/snapshot/snapshot-row.ts` (pure order-row builder, T023), `apps/api/test/helpers/drill-total.ts` (T038), `apps/api/test/helpers/perf-search-data.ts` (T018).
- D14. **The 002 baseline** (T002) is taken before any change and protects the extraction of the entity where-builder (T009) and the index-backed `q` filter.
- D15. **US6's API is built before US1** (Phase 3) because Home consumes it and FR-021 needs it. US6's web card is in Phase 8 (T052).
- D16. **MVP** = the three P1 stories (Search, Home totals, drill-down): Phases 1 to 7 (T001 to T045). Search is independently shippable at the Phase 4 checkpoint.
